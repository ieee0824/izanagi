# v0.2.8

通常の eBPF syscall ログで、`connect` の宛先 IP・ポートと実際の戻り値を記録できるようになりました。

## 修正

- IPv4 / IPv6 の接続先を開始時に取得し、スレッドごとに終了イベントと対応付けます。
- 接続成功は `0`、接続拒否は `err=111` のように記録します。`EINPROGRESS` は成功と区別します。
- `NetworkAllowlistRule` が connect の宛先 IP を判定できるようになりました。警告は通信の遮断を意味しません。
- 状態がない終了経路で未初期化レジスタを参照し、Linux verifier に拒否される問題を修正しました。

関連: [PR #120](https://github.com/ieee0824/izanagi/pull/120)、[Issue #119](https://github.com/ieee0824/izanagi/issues/119)。

## 更新時の注意

raw eBPF ABI を **2 から 3** に更新しました。ホスト・guest agent・eBPF オブジェクトを同時に更新し、
既存 VM を停止してイメージを再作成してください。古い agent / eBPF オブジェクトの組み合わせは互換性検査で拒否されます。
認証付き wire protocol は変更していません。VM イメージはリリース資産に含まれません。

```bash
make build
make install
make qemu-image
```

## 検証と制約

更新した QEMU VM で IPv4 / IPv6 の成功・拒否、4 スレッド並行接続、非同期 connect の戻り値を実測し、
宛先と syscall 結果の一致を確認しました。

AF_UNIX と sendto の宛先展開は対象外です。非同期 connect の最終接続状態は、この syscall 結果だけでは判定できません。
開始・終了の両イベントに警告が出るため、警告件数をそのまま接続試行回数として数えないでください。
未対応 family・不正 sockaddr・IPv6 scope の実機確認は未実施です。

## 配布物

macOS / Linux の ARM64・x86_64 向けアーカイブと `SHA256SUMS` を提供します。
Linux アーカイブは guest agent と eBPF オブジェクトを同梱します。
配布条件は [バイナリリリース手順](https://github.com/ieee0824/izanagi/blob/v0.2.8/docs/releases.md) を参照してください。
